Selected work

Four projects that show how I work: a real problem, a small and testable solution, and honest notes on what is still missing.

  • 01 / RAG · API

    Harvest-AIsights

    Asking an LLM about commodity prices invites invented numbers. This API first retrieves the matching market records, then lets Gemini answer from them and returns the sources (file and row).

    • Python
    • FastAPI
    • Gemini
    • ChromaDB
    • Sentence Transformers
    • pytest
    • Docker
    Details
    • What it does: answers natural-language questions about 131 agricultural quotations (Euronext, CBOT, Argus and physical markets), with short per-session conversation memory.
    • Key decisions: each CSV row becomes a self-contained text record, embedded with multilingual-e5-small and stored in ChromaDB. Retrieved content is treated as untrusted data in the prompt.
    • Quality: retrieval measured with Hit@K and MRR; pytest suite with mocked embedding and LLM; Dockerfile and GitHub Actions CI.
    • What I learned: RAG is weak at aggregation, because the LLM only sees the top-K records. Exact statistics therefore come from a separate /quotes/summary endpoint.

    Status: portfolio prototype, in active development.

  • 02 / Mobile · AI

    UniScribe

    Android

    Taking notes while listening to a lecture is hard. UniScribe records the lecture and returns a title, a full transcript, a structured summary and key points.

    • Kotlin
    • Jetpack Compose
    • Room
    • Firebase AI Logic
    • Gemini
    • PWA
    Details
    • What it does: a native Android app and a static web app (PWA). Record or upload audio, get study notes, keep a history on the device and export to .txt.
    • Key decisions: no server of my own and no API key in the clients. Both call Gemini through Firebase AI Logic, protected by App Check, and the response is constrained to a JSON schema.
    • Android details: a foreground service keeps recording with the screen off; the model and the recording limit can be changed with Remote Config.
    • What I learned: shipping takes more than code. A Play release needs signing, a Data safety form and a closed test with 12 testers for 14 days.

    Status: code complete; device testing and the Google Play closed test are next.

    Code for UniScribe on GitHub (opens in a new tab)
  • 03 / Data · CLI

    ExcelFlow

    Supplier spreadsheets arrive with different headers, languages and date formats. ExcelFlow cleans and validates them into one consolidated workbook, plus a report of every issue found.

    • Python
    • pandas
    • openpyxl
    • pytest
    • GitHub Actions
    Details
    • What it does: a command-line pipeline: header detection → column mapping → cleaning → validation → Excel report and issues CSV.
    • Key decisions: column names are matched across French, Portuguese and English headers and small typos. Six validation rules, and every issue is traced to its file, Excel row, field and reason.
    • Results: on synthetic data with injected errors, 10,120 rows in 2.59 s (median) with 100% precision and recall for the implemented rules.
    • What I learned: a ground-truth dataset turns "it seems to work" into a measurable result.
    Code for ExcelFlow on GitHub (opens in a new tab)
  • 04 / Mobile

    Noble Chess Clock

    Android

    A chess game needs a fair, readable timer. This two-player clock lets each player tap their side to end the turn and start the opponent's time.

    • React Native
    • Expo
    • JavaScript
    Details
    • What it does: a setup screen with time presets (1 to 180 minutes per player) and an optional increment of up to 60 seconds per move, plus pause and resume.
    • Key decisions: a visual identity inspired by classic chess rooms (dark wood and aged gold), with high-contrast digits that stay easy to read.
    • Tooling: runs on an Android phone through Expo Go, with an EAS Build path prepared for a release build.
    • What I learned: state and timing logic in a mobile UI, and preparing an Expo project for an Android build.
